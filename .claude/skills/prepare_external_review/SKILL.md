# prepare_external_review

2段レビューの1段目（外部LLMによるレビュー）に投げるプロンプトを組み立てます。運用規則とプロンプト雛形は [docs/external_review.md](../../../docs/external_review.md) が正本です。

このスキルはファイルを組み立てるだけで、レビューそのものは行いません。**草稿の語句を要約・改変せず、そのまま埋め込みます。**

## 手順

1. **対象サイクルの特定**: 引数でサイクルディレクトリが指定されていればそれを使う。指定がなければ、`reviews/` 直下で最新（ディレクトリ名の日付降順。日付は山行日）かつ `review_external.md` 未作成のものを候補として提示し、ユーザーに確認する。`draft.md` を Read する。
2. **重点ポイントの確認**: `draft.md` の frontmatter に `review_focus` があれば読み込む。引数や会話でコメントが渡されていればそれも使う。どちらも無い場合は、一度だけ「重点的に見てほしいポイントや気になっている点はありますか？（任意。無ければこのまま進めます）」と確認する。無ければ該当見出しごと省略する。
3. **同梱する資料の読み込み**:
   - [guidelines/review_guideline.md](../../../guidelines/review_guideline.md) の**セクション1（核）**と、変更履歴の最新日付
   - [guidelines/style_profile.md](../../../guidelines/style_profile.md) の全文（未蒸留なら該当見出しごと省略する）
   - **セクション2（彩り）は読み込まない・渡さない。** これは意図的な設計で、観点の多様性を確保するための要（[docs/external_review.md](../../../docs/external_review.md) セクション1）
4. **プロンプトの組み立て**: [docs/external_review.md](../../../docs/external_review.md) セクション3の雛形に、手順2〜3で得た内容と `draft.md` の本文（frontmatter を除く）を差し込む。ガイドラインと文体プロファイルは**ファイルから読んだ本文をそのまま貼り**、要約しない。
5. **書き出し**: `tmp/external_prompt_<slug>.md` として Write する（`<slug>` はサイクルディレクトリ名。`tmp/` は git 管理外）。既存ファイルがあれば上書き前にユーザーに確認する。
6. **報告**: 書き出したパスと、次の3点を簡潔に伝える。
   - このファイルの内容をそのまま外部LLMに渡すこと（リポジトリを直接読めるツールなら、このファイルを指定してもよい）
   - 同梱したガイドラインの版（変更履歴の最新日付）と、重点ポイントを渡したかどうか
   - 応答が返ったら `/register_external_review` で取り込むこと

## 注意

- `tmp/` は git 管理外のため、生成物は履歴に残らない。後から必要になったら再生成すればよい（ガイドラインが更新されていれば新しい版で組み直される）。
- 生成したプロンプト全文をチャットに貼り出さない（草稿全文を含むため）。パスと要点のみ報告する。
