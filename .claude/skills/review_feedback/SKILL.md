# review_feedback

一定期間にたまったレビューサイクルをまとめて振り返り、レビューガイドラインの改善につなげるスキルです。

## 前提・思想

- **手動起動**: 自動実行はしません。完了サイクルが3〜5件たまった頃、または月1回程度を目安に、ユーザーが起動したときだけ動きます。
- **採用/棄却の一次情報は diff**: 「どの提案が採用されたか」は、draft.md（原稿）・review_*.md（提案）・final.md（公開版）の突き合わせで推定します。ユーザーに評価記録の手間を求めないための設計です。ただし `notes.md` がある場合は、diff からの推定よりそちらの明示的な所感を優先します。
- **human-in-the-loop**: ガイドラインの書き換えは必ず**修正差分案を提示し、ユーザーが承認してから**反映します。勝手に `guidelines/review_guideline.md` を編集しないでください。
- **「核 / 彩り」2層モデル**: 核（構成維持・事実の保全・全文リライト方式・著者の声）は安易に動かさず、彩り（レビューの重点・表現の好み）は積極的に調整します。この非対称が要です。
- **体制フェーズごとに扱いを変える**: レビュー体制は時期によって異なります（[CLAUDE.md](../../../CLAUDE.md)「運用状況」の体制フェーズ参照）。対象期間が複数フェーズにまたがる場合は、集計を混ぜずフェーズ別に出したうえで、全体の傾向を述べます。
  - **並走期**（`review_gemini.md` が存在するサイクル）: Claude と Gemini が独立にレビューしていた期間。Gemini 側の提案も採用分析の材料に含めます（採用傾向の観察が目的で、レビュアーの優劣判定は不要）。
  - **Claude 単独期**（`review_claude.md` のみ）: 従来どおりの集計。
  - **2段レビュー期**（`review_external.md` と `review_claude.md` が揃うサイクル）: 外部レビュー → Claude の突き合わせという順序があるため、ステップ2・3の専用の観点を追加で見ます。

## 手順

### ステップ0: 対象期間の決定

1. [meta/review_markers.md](../../../meta/review_markers.md) の最新エントリを確認する。
2. **dateFrom** = 最新エントリの対象期間末日の翌日、**dateTo** = 今日（JST）。ここでいう対象期間の日付は、公開日ではなくサイクルディレクトリ名に使っている**山行日**を指す。エントリが1件も無い（初回）場合は、`reviews/` の最古のサイクルの日付を dateFrom にする。
3. 決めた期間をユーザーに一言示してから次へ進む。

### ステップ1: 対象サイクルの収集

1. `reviews/` 直下で、ディレクトリ名の日付（山行日）が期間内のサイクルを列挙し、各ファイル（draft / review_external / review_claude / final / notes、および並走期のサイクルにのみ存在する review_gemini）の有無を表にする。
2. 各サイクルがどの体制フェーズかを判定し、表に併記する（`review_external.md` の有無で2段レビュー期を判別。`reviewer` / `model` も控える）。
3. `final.md` が無いサイクルは**未完了**として集計対象から外す（次回に持ち越し。マーカーの持ち越し件数に記録する）。
4. 完了サイクルが0件なら、その旨を伝えて終了する（マーカーは更新しない）。

### ステップ2: 採用分析（サイクルごと）

各完了サイクルについて:

1. draft.md / review_external.md（あれば）/ review_claude.md（あれば）/ review_gemini.md（並走期のサイクルにあれば）/ final.md を読み込む。
2. レビューの指摘・リライト提案のそれぞれについて、final での扱いを推定する: **採用**（ほぼそのまま反映）/ **部分採用**（形を変えて反映）/ **棄却**（原稿のまま、または別の形に修正）。
3. `notes.md` があれば、diff からの推定より優先して解釈に反映する。
4. 指摘を**カテゴリ分け**して整理する。カテゴリはガイドライン セクション2（彩り）の観点名を基本とし、当てはまらないものは新カテゴリ候補として控える（例: 冗長表現の圧縮 / 描写の具体化 / 語順・接続 / 構成 / 事実関係の確認 / 語彙選択）。
5. **2段レビュー期のサイクルでは、加えて次を記録する**（`review_claude.md` の出所ラベルと外部レビューの検証結果を用いる）。
   - **出所別の扱い**: 各指摘が `[両者一致]` / `[外部]` / `[Claude]` のどれで、final でどう扱われたか。
   - **突き合わせ判定の妥当性**: Claude が「不採用」と判定した外部提案をユーザーが最終稿で採用していれば**取りこぼし**、「採用推奨」とした提案が棄却されていれば**過剰採用**として記録する。これは Claude の突き合わせ精度そのものの評価であり、2段レビュー期で最も重要な観測点。
   - **ガイドライン外の指摘**: 「観点: ガイドライン外」と記された外部由来の指摘が採用されていれば、**彩りの新規項目候補**として控える（外部LLMには彩りを渡していないため、ここにガイドラインの穴が現れる）。

### ステップ3: 傾向集計

- **カテゴリ別の採用率**（全サイクル合算。件数と割合の表）。完了サイクルが3件未満の場合はサンプルが小さい旨を明記し、参考値として扱う。
- **2段レビュー期の補足集計**（該当サイクルがある場合）:
  - **出所別の採用率**: `[両者一致]` / `[外部]` / `[Claude]` それぞれの採用・部分採用・棄却。両者一致の指摘が特に高採用なら、突き合わせが効いている証拠として扱う。
  - **突き合わせ判定の精度**: 取りこぼし件数 / 過剰採用件数と、その内容の共通点。繰り返し取りこぼす種類があれば、ガイドライン セクション4（3判定の基準）の修正候補。
  - **ガイドライン外から来て採用された指摘**: 彩りへの新規項目候補として列挙する。
- **並走期の補足集計**（過去分で review_gemini と review_claude が両方あるサイクルのみ）: 同一 draft への指摘の重なり / カテゴリ別採用率の差。ガイドラインに反映できる採用傾向が読み取れる場合のみ扱い、無ければ省略してよい。
- **繰り返し棄却されるパターン** = ガイドラインで抑制・修正すべき候補。**繰り返し採用されるパターン** = 強化・明文化すべき候補。1回だけの事象より、複数サイクルで繰り返されたものを優先する。

### ステップ4: 核 / 彩りの仕分け

ステップ2〜3の結果を、ガイドラインの2層へ仕分ける。

- **核への違反**（構成を変えてきた、事実を書き換えた、リライトが部分的だった、文体が別人になった等）→ 核を**締める**方向の文言修正。**違反の出所（外部レビュー由来 / Claude 由来）を分けて集計する。** 外部由来の違反が Claude の検証で止められていれば体制が機能している証拠なので核の修正は不要で、最終稿まで通っていた場合のみ核またはセクション4を締める。
- **彩りへの調整** → 2方向がある。
  - **抑制**: 繰り返し棄却される観点の重みを下げる／表現を限定する。
  - **強化**: 繰り返し採用される観点を明文化する／重みを上げる。ステップ2-5で控えた「ガイドライン外から来て採用された指摘」もここで扱う。
- **セクション4（突き合わせ）への調整**: 取りこぼし・過剰採用の傾向が読み取れる場合、3判定の基準や検証の優先順位を修正する候補として挙げる。
- **衝突判定**: 2つの傾向が本当に矛盾するのは**同じ層の同じ観点**に相反する結果が出たときだけ。その場合のみ、どちらを採るかの判断ポイントとしてユーザーに明示する。

### ステップ5: ガイドライン修正差分案の提示（承認 → 反映）

1. `guidelines/review_guideline.md` への具体的な修正差分案を before/after で提示する。各案には**根拠**（ステップ2〜3の採用率・件数・該当サイクル）を添える。
2. **ユーザーが承認した項目だけ** Edit で反映する。未承認・保留の項目は反映しない。
3. 反映した場合は、ガイドラインの変更履歴に日付と要約を追記する。

### ステップ6: マーカーの追記

[meta/review_markers.md](../../../meta/review_markers.md) の説明文直下（既存エントリの上）に、同ファイル記載のエントリ形式で1件追記する。対象サイクルの体制フェーズも記載する。

## 出力（ユーザーへの報告）

1. 対象期間と対象サイクル数（完了 / 未完了持ち越し）、および体制フェーズの内訳。
2. カテゴリ別採用率の表と、繰り返し現れた採用・棄却パターン。
3. 2段レビュー期の補足集計（出所別採用率 / 突き合わせ判定の精度 / ガイドライン外から採用された指摘）。該当サイクルがある場合のみ。
4. 並走期の補足集計（過去分で該当サイクルがある場合のみ）。
5. 核 / 彩り / セクション4の仕分け結果（衝突があればその判断ポイント）。
6. 提示したガイドライン修正案と、承認・反映の有無。
7. 追記したマーカーの内容。
