# 外部レビューの運用規則

レビューは **外部LLMによる1回目** と **Claude による2回目（突き合わせ）** の2段で行います。この文書は1回目（外部レビュー工程）の運用規則と、外部LLMへ渡すプロンプトの雛形を定めます。

関係するスキル: `prepare_external_review`（プロンプト生成）/ `register_external_review`（応答の取り込み）/ `review_report`（突き合わせ）。突き合わせ側の方針は [guidelines/review_guideline.md](../guidelines/review_guideline.md) セクション4 が正本です。

## 1. 外部LLMに渡すもの・渡さないもの

| | 渡す | 理由 |
| --- | --- | --- |
| 草稿本文（draft.md の本文） | ○ | レビュー対象 |
| 重点ポイント（`review_focus`） | ○ | 著者の悩みは両レビュアーに共有する |
| review_guideline.md セクション1（核） | ○ | 事実の創作・構成の変更・部分添削・文体逸脱という致命的な事故を防ぐ |
| review_guideline.md セクション3（出力形式） | ○ | 突き合わせと採用分析のため形式を揃える |
| style_profile.md | ○ | 核の「著者の声の尊重」を外部LLMが実行するために必要 |
| **review_guideline.md セクション2（彩り）** | **×** | 観点を共有すると Claude と同質の指摘しか出ず、2回レビューする意味が薄れる |
| 過去のレポート・過去サイクルのレビュー | × | 事実の混入を防ぐ。コンテキスト分離の原則は外部レビューにも適用する |

**彩り（観点）を渡さないことが、この体制の要です。** ガイドラインの外から来た有効な指摘は、メタレビュー（`review_feedback`）で彩りの新規項目候補として扱います。

## 2. 外部LLMに求める出力形式

`review_claude.md` と揃えた3部構成とします。

1. **総評**（3〜5行）
2. **指摘一覧**（番号付き）: 対象箇所の引用 / 指摘の理由 / 修正提案
3. **全文リライト案**: セクション構成を維持したほぼ全文

Claude 版と異なり、指摘に「根拠となる観点名」は求めません（彩りを渡していないため）。リライト案本文には `［※指摘N］` の形で該当箇所にマーカーを埋め込んでもらいます（突き合わせ時の対応付けに使う。番号は Claude 側で振り直します）。

## 3. プロンプト雛形

`prepare_external_review` が以下を組み立て、`tmp/external_prompt_<slug>.md`（git 管理外）に書き出します。`{{ }}` はスキルが差し込む箇所で、**ガイドラインと文体プロファイルはファイルから読んでそのまま貼る**（この文書に写しを置かない＝二重管理を避ける）。

---

````markdown
あなたは登山レポートのレビュアーです。以下の草稿をレビューしてください。
このレポートは YAMAP で公開される、公共交通機関を主に使う登山者の山行記録です。

## 絶対に守ること

{{guideline_section1}}

## 著者の文体プロファイル

原文の語り口を別人の文章にしないため、以下の傾向を踏まえてください。

{{style_profile}}

## 重点的に見てほしいポイント（著者からのコメント）

{{review_focus}}

## 出力形式

次の3部構成で出力してください。

1. **総評**（3〜5行）: 草稿全体の印象と、リライトで注力した方向性。
2. **指摘一覧**（番号付き）: 各項目に「対象箇所の引用」「指摘の理由」「修正提案」を書く。
3. **全文リライト案**: セクション構成と順序を維持した、ほぼ全文のリライト。該当箇所には `［※指摘N］` の形でマーカーを埋め込む。

## 草稿

{{draft_body}}
````

---

- `{{review_focus}}` が無いサイクルでは、その見出しごと省略する。
- `{{guideline_section1}}` は review_guideline.md のセクション1（核）本文。セクション2（彩り）は**含めない**。
- 出力形式の記述は本文書セクション2と review_guideline.md セクション3を合わせたもので、雛形に直接書く（外部LLMは指摘マーカーの詳細規則を知らないため、簡略形の `［※指摘N］` を指定する）。

## 4. 応答の取り込み

`register_external_review` が `reviews/<cycle>/review_external.md` として保存します。

- 変換は [text_to_markdown.md](text_to_markdown.md) に従い、**語句を一切変えない**。
- 挨拶・前置き・自己言及（「拝見しました！」等）も削らずそのまま残す。レビュアーの癖はメタレビューの材料になる。
- 3部構成が揃っていない場合も保存はし、欠けている部を報告する（突き合わせ側で吸収する）。
- frontmatter:

  ```yaml
  ---
  reviewer: cursor              # 外部レビューを実行したツール／サービス名
  model: claude-sonnet-4.5      # 分かる場合のみ。不明なら unknown
  reviewed_at: 2026-09-03       # 取り込み日（JST）
  guideline_updated_at: 2026-08-20   # プロンプトに用いたガイドラインの変更履歴の最新日付
  review_focus: |               # 渡した重点ポイントがあれば
    ...
  ---
  ```

## 5. 外部LLMを差し替えるとき

ファイル名は `review_external.md` で固定しており、モデル名はファイル名に含めません。差し替え時の手順は次の2点だけです。

1. `register_external_review` で `reviewer` / `model` に新しい値を記録する。
2. [CLAUDE.md](../CLAUDE.md)「運用状況」の体制フェーズに、切り替え日と新しいレビュアーを1行追記する。

スキルやガイドラインの書き換えは不要です。メタレビューは frontmatter の `reviewer` を見てレビュアー別に集計します。
